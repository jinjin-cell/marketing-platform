# 大营销抽奖系统 前端接口文档

> 版本：v1.0（对应后端接口版本 `v1`）
> 日期：2026-09-12
> 后端服务：`marketing-platform-app`（Spring Boot 2.7 + DDD 分层，端口 `8091`）
> 接口来源：`marketing-platform-trigger` 模块 `RaffleActivityController` / `RaffleStrategyController`

---

## 1. 通用约定

### 1.1 基础地址

```
开发环境：http://localhost:8091/api/v1
```

- `api-version` 取自后端配置 `app.config.api-version`，当前为 `v1`。
- 后端 dev 环境已配置 `@CrossOrigin("*")`，前端可直连，无需代理。

### 1.2 统一响应结构

所有接口返回统一 `Response` 包装：

```json
{
  "code": "0000",
  "info": "调用成功",
  "data": { }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | String | 状态码，`0000` 表示成功 |
| info | String | 状态说明 |
| data | Object/Array/Boolean/Number | 业务数据，失败时可能为 `null` |

> 前端拦截器统一判断 `code === "0000"`；非 `0000` 时按错误码表（§2）映射提示文案。

### 1.3 请求格式

| 接口类型 | Content-Type | 示例 |
| --- | --- | --- |
| JSON 请求体 | `application/json` | draw、query_user_activity_account 等 |
| 表单参数 | `application/x-www-form-urlencoded` | calendar_sign_rebate、is_calendar_sign_rebate（`@RequestParam`） |
| URL 查询参数 | - | 业务查询接口（GET） |

### 1.4 通用请求参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| userId | String | 是 | 用户 ID（前端简化登录产生，存 localStorage） |
| activityId | Long | 是 | 活动 ID，默认 `100301` |

## 2. 错误码表（ResponseCode）

### 2.1 通用码

| code | info | 前端提示建议 |
| --- | --- | --- |
| 0000 | 调用成功 | - |
| 0001 | 调用失败 | 网络异常，请稍后重试 |
| 0002 | 非法参数 | 参数错误 |
| 0003 | 唯一索引冲突 | 操作已受理，请勿重复提交 |
| 0004 | 活动已降级 | 活动太火爆，请稍后再试（禁用抽奖入口） |
| 0005 | 访问限流拦截 | 操作太频繁啦，休息一下再试 |
| 0006 | 访问熔断拦截 | 服务繁忙，请稍后再试 |

### 2.2 业务码（ERR_BIZ_*）

| code | info | 场景 |
| --- | --- | --- |
| ERR_BIZ_001 | 策略规则权重规则未配置 | 权重规则查询 |
| ERR_BIZ_002 | 抽奖策略配置未装配，请先完成装配 | 抽奖前未调用装配接口 |
| ERR_BIZ_003 | 活动未开启（非 open 状态） | draw / 兑换 |
| ERR_BIZ_004 | 非活动日期范围 | draw / 兑换 |
| ERR_BIZ_005 | 活动库存不足 | draw / 兑换 |
| ERR_BIZ_006 | 账户总额度不足 | draw |
| ERR_BIZ_007 | 账户月额度不足 | draw |
| ERR_BIZ_008 | 账户日额度不足 | draw（提示"今日次数已用完，明天再来或去兑换"） |
| ERR_BIZ_009 | 用户抽奖单已使用过，不可重复抽奖 | draw 重复请求 |
| ERR_BIZ_010 | 活动账户操作加锁超时，请稍后重试 | draw / 兑换 |
| ERR_BIZ_011 | 积分账户操作加锁超时，请稍后重试 | 兑换 |

## 4. 活动模块接口（/api/v1/raffle/activity）

### 4.1 活动装配（数据预热）

活动 SKU 库存和策略概率表由后端在缓存缺失时懒初始化。装配能力只保留给内部服务调用，不暴露 HTTP 路由，前端不得触发库存装配。

### 4.2 活动抽奖（大转盘核心接口）

创建参与订单 → 执行抽奖 → 写入中奖记录，一次调用完成。**后端按用户限流 1 次/秒**。

- **URL**：`POST /api/v1/raffle/activity/draw`
- **Content-Type**：`application/json`
- **请求参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| userId | String | 是 | 用户 ID |
| activityId | Long | 是 | 活动 ID |

- **请求示例**：

```json
{ "userId": "qijiv", "activityId": 100301 }
```

- **响应示例**：

```json
{
  "code": "0000",
  "info": "调用成功",
  "data": {
    "awardId": 107,
    "awardTitle": "随机积分",
    "awardIndex": 4,
    "awardConfig": "1,100"
  }
}
```

- **响应字段**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| awardId | Integer | 奖品 ID |
| awardTitle | String | 奖品标题（弹窗展示） |
| awardIndex | Integer | 奖品排序编号，**与 query_raffle_award_list 的 sort 对应，用于转盘定位** |
| awardConfig | String | 奖品配置透传（积分范围 `1,100` 等，可解析展示） |

- **业务错误**：`0004/0005/ERR_BIZ_003~010`（见错误码表）。
- **前端注意**：抽奖动画时长 ≥ 1.5s 并禁用按钮，规避限流；成功后需刷新额度、奖品列表、权重规则。

### 4.3 日历签到返利

签到并发放行为返利（积分，MQ 异步到账）。

- **URL**：`POST /api/v1/raffle/activity/calendar_sign_rebate`
- **Content-Type**：`application/x-www-form-urlencoded`
- **请求参数**（Form）：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| userId | String | 是 | 用户 ID |

- **请求示例**：

```
userId=qijiv
```

- **响应示例**：

```json
{ "code": "0000", "info": "调用成功", "data": true }
```

- **前端注意**：`0003`（唯一索引冲突）视为"今日已签到"；返利到账有延迟，积分余额延迟几秒刷新。

### 4.4 查询今日是否已签到

- **URL**：`POST /api/v1/raffle/activity/is_calendar_sign_rebate`
- **Content-Type**：`application/x-www-form-urlencoded`
- **请求参数**（Form）：同 4.3（`userId`）。
- **响应示例**：

```json
{ "code": "0000", "info": "调用成功", "data": true }
```

- **说明**：`data=true` 今日已签到；`data=false` 未签到。进入签到页时调用。

### 4.5 查询用户活动账户额度

- **URL**：`POST /api/v1/raffle/activity/query_user_activity_account`
- **Content-Type**：`application/json`
- **请求参数**：

| 参数 | 类型 | 必填 |
| --- | --- | --- |
| userId | String | 是 |
| activityId | Long | 是 |

- **响应示例**：

```json
{
  "code": "0000",
  "info": "调用成功",
  "data": {
    "totalCount": 10,
    "totalCountSurplus": 8,
    "dayCount": 3,
    "dayCountSurplus": 2,
    "monthCount": 5,
    "monthCountSurplus": 4
  }
}
```

- **响应字段**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| totalCount / totalCountSurplus | Integer | 总额度 / 总剩余 |
| dayCount / dayCountSurplus | Integer | 日额度 / 日剩余 |
| monthCount / monthCountSurplus | Integer | 月额度 / 月剩余 |

- **说明**：未充值过额度的用户返回全 0 稳定结构，前端无需处理 null。**可用抽奖次数取三者剩余的最小值**。

### 4.6 积分兑换活动商品

用积分兑换 SKU（购买抽奖次数）。后端自动生成幂等业务号。

- **URL**：`POST /api/v1/raffle/activity/credit_pay_exchange_sku`
- **Content-Type**：`application/json`
- **请求参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| userId | String | 是 | 用户 ID |
| sku | Long | 是 | SKU 编号（来自商品列表） |

- **请求示例**：

```json
{ "userId": "qijiv", "sku": 10030101 }
```

- **响应示例**：

```json
{ "code": "0000", "info": "调用成功", "data": true }
```

- **业务错误**：`ERR_BIZ_003/004/005`（活动状态/日期/库存）、`ERR_BIZ_011`（积分账户锁超时）；积分不足时后端返回业务异常。
- **前端注意**：成功后刷新积分余额、账户额度、商品列表。

### 4.10 查询日历签到记录（区间，V1.2 新增）

查询指定日期区间内已完成的签到日期，供签到页日历渲染整月标记。

> 为什么需要这个接口：签到标记曾只记录在浏览器 `localStorage`（key 为 `sign_dates_<userId>`），
> 换设备、换域名（如 localhost:5173 → http://111.228.17.153）或清理缓存后历史全部丢失，
> 表现为"昨天明明签到了，日历上却没有昨天的标记"。签到数据始终在后端
> `user_behavior_rebate_order` 表（`out_business_no = yyyy-MM-dd`），本接口把它暴露给前端。

- **URL**：`GET /api/v1/raffle/activity/query_calendar_sign_rebate_list`
- **请求参数**（Query）：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| userId | String | 是 | 用户 ID |
| beginDate | String | 否 | 起始日期 `yyyy-MM-dd`（含），为空取当月 1 号 |
| endDate | String | 否 | 结束日期 `yyyy-MM-dd`（含），为空取当月最后一天 |

- **请求示例**：

```
GET /api/v1/raffle/activity/query_calendar_sign_rebate_list?userId=qijiv&beginDate=2026-08-30&endDate=2026-10-03
```

- **响应示例**：

```json
{
  "code": "0000",
  "info": "调用成功",
  "data": {
    "serverDate": "2026-09-14",
    "beginDate": "2026-08-30",
    "endDate": "2026-10-03",
    "signDates": ["2026-09-12", "2026-09-14"]
  }
}
```

- **响应字段**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| serverDate | String | 服务端当天日期，前端用它校准"今天" |
| beginDate / endDate | String | 实际生效的查询区间 |
| signDates | String[] | 区间内已签到日期，升序去重 |

- **说明**：
  1. 前端按月历可视范围（本月 1 号所在周的周日 ~ 本月最后一天所在周的周六）请求，因此区间可能跨 3 个月；
  2. 区间跨度上限 62 天，`endDate < beginDate` 或跨度超限返回 `0002`；
  3. **签到业务日期以服务端为准**（服务端 `LocalDate.now()`），浏览器时区与服务端不一致时，
     请用 `serverDate` 判断"今天"，不要用浏览器本地日期，否则会出现"标记落在今天、记录落在前一天"的错位。

## 5. 策略模块接口（/api/v1/raffle/strategy）

### 5.1 策略装配

策略概率表在首次抽奖时懒初始化。装配能力只保留给内部服务调用，不暴露 HTTP 路由。

### 5.2 查询抽奖奖品列表（转盘数据源）

获取转盘扇区奖品及每个奖品的解锁状态。

- **URL**：`POST /api/v1/raffle/strategy/query_raffle_award_list`
- **Content-Type**：`application/json`
- **请求参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| activityId | Long | 是 | 活动 ID |
| userId | String | 是 | 用户 ID |
| strategyId | Long | 否 | 已废弃，可不传 |

- **请求示例**：

```json
{ "userId": "qijiv", "activityId": 100301 }
```

- **响应示例**：

```json
{
  "code": "0000",
  "info": "调用成功",
  "data": [
    {
      "awardId": 101,
      "awardTitle": "随机积分",
      "awardSubTitle": "1至100积分",
      "sort": 1,
      "awardRuleLockCount": 10,
      "isAwardUnlock": false,
      "waitUnlockCount": 3
    },
    {
      "awardId": 107,
      "awardTitle": "五等奖",
      "awardSubTitle": "增加66次抽奖",
      "sort": 2,
      "awardRuleLockCount": null,
      "isAwardUnlock": true,
      "waitUnlockCount": 0
    }
  ]
}
```

- **响应字段**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| awardId | Integer | 奖品 ID |
| awardTitle | String | 奖品标题（扇区主文案） |
| awardSubTitle | String | 奖品副标题（扇区副文案） |

| awardRuleLockCount | Integer | 抽奖 N 次解锁；null 表示无解锁限制 |
| isAwardUnlock | Boolean | 当前用户是否已解锁该奖品 |
| waitUnlockCount | Integer | 还差 N 次抽奖解锁（0 = 已解锁/无限制） |


- **响应字段**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| ruleWeightCount | Integer | 达到该抽奖次数后解锁的必中档位 |
| userActivityAccountTotalUseCount | Integer | 用户在活动下累计已抽奖次数 |
| strategyAwards | Array | 该档位必中奖品范围 |

- **前端建议**：返回全部档位，前端展示一条已达标的最大档位，或一条最近将达成的档位（`ruleWeightCount - userActivityAccountTotalUseCount` 最小的正数）。

### 5.4 随机抽奖（演示接口）

不落订单、不消耗额度的策略方法可能绕过活动账户约束，因此已移除 HTTP 路由。正式页面只能使用 4.2 `draw`。

## 6. 典型调用时序

### 6.1 进入活动主页

```
1. POST /raffle/strategy/query_raffle_award_list           ← 渲染转盘
2. POST /raffle/strategy/query_raffle_strategy_rule_weight ← 渲染必中提示
3. POST /raffle/activity/query_user_activity_account       ← 渲染额度
```

### 6.2 点击抽奖

```
1. POST /raffle/activity/draw                              ← 拿到 awardIndex
2. 转盘旋转动画（≥1.5s）停止到 awardIndex 对应扇区
3. 中奖弹窗（awardTitle）
4. 并行刷新：query_raffle_award_list、query_user_activity_account、query_raffle_strategy_rule_weight
```

### 6.3 签到页

```
1. GET  /raffle/activity/query_calendar_sign_rebate_list  ← 初始化：整屏签到标记 + serverDate（校准“今天”）
2. 用户点击签到 → POST /raffle/activity/calendar_sign_rebate
3. 重新拉取步骤 1 的接口刷新标记
4. 延迟刷新积分余额（GET /raffle/activity/query_user_credit）
5. 切换月份时按新的可视区间重新拉取步骤 1
```

> 注：`POST /raffle/activity/is_calendar_sign_rebate` 仍可用于只判断"今天签没签"的场景，
> 签到页已改为直接由步骤 1 的 `signDates` 推导，少一次请求。

### 6.4 兑换页

```
1. GET  /raffle/activity/query_sku_product_list           ← 商品列表
2. GET  /raffle/activity/query_user_credit                ← 积分余额
3. 用户点击兑换 → POST /raffle/activity/credit_pay_exchange_sku
4. 刷新：积分余额、账户额度、商品列表
```

### 8.3 查询活动列表（多活动切换）

- **URL**：`GET /api/v1/raffle/activity/query_activity_list`
- **请求参数**：无
- **响应示例**：

```json
{
  "code": "0000",
  "info": "调用成功",
  "data": [
    {
      "activityId": 100301,
      "activityName": "抽奖活动",
      "activityDesc": "幸运大转盘",
      "state": "open",
      "stateDesc": "开启",
      "beginDateTime": "2026-01-01 00:00:00",
      "endDateTime": "2026-12-31 23:59:59"
    }
  ]
}
```

- **前端用法**：进入首页时调用，活动 ID 存 `localStorage.activityId`；
  列表多于 1 个时首页展示活动下拉框，切换后重新装配并刷新奖品/额度。
  接口失败时回落到 `VITE_ACTIVITY_ID`（默认 100301）。

### 8.4 DCC 开关查询与修改（运维）

- **查询**：`GET /api/v1/raffle/dcc/query_config` → `data: { "degradeSwitch": "open", "rateLimiterSwitch": "close" }`
- **修改**：`GET /api/v1/raffle/dcc/update_config?key=degradeSwitch&value=open`
  - `key` 仅允许 `degradeSwitch`、`rateLimiterSwitch`；`value` 仅允许 `open`、`close`
  - 修改立即生效（ZooKeeper 推送，无需重启）

| 开关 | 语义 |
| --- | --- |
| degradeSwitch | **非 open 即人工降级**：抽奖接口直接返回 `0004 活动已降级` |
| rateLimiterSwitch | `open` 开启 Redis 每用户限流（抽奖 1 次/秒），`close` 关闭 |

### 8.5 定时任务手动触发（运维）

- **任务清单**：`GET /api/v1/raffle/admin/query_job_list`
- **手动触发**：`GET /api/v1/raffle/admin/run_job?job=<任务名>&token=<运维令牌>`
  - 令牌取配置 `app.config.admin-token`（环境变量 `ADMIN_TOKEN`，默认 `qijiv-admin`）
  - 同步执行，任务内部有 Redisson 抢占锁，队列空即结束，重复触发安全

| 任务名 | 说明 |
| --- | --- |
| updateAwardStock | 更新奖品消耗库存（Redis 队列落库） |
| updateActivitySkuStock | 更新活动 SKU 库存（Redis 队列落库） |
| updateActivityOrderExpired | 将超过一个月的待支付订单置为过期 |
| sendMessageTaskDb1 | 补偿发送 ds1 库未发送的 MQ 任务 |
| sendMessageTaskDb2 | 补偿发送 ds2 库未发送的 MQ 任务 |

> 页面对应 `/admin` 路由（入口在「我的」页底部），任务平时仍由 xxl-job-admin 调度。
