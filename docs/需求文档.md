# 大营销抽奖系统 前端需求文档

> 版本：v1.0
> 日期：2026-09-12
> 配套后端：marketing-platform（DDD 营销平台，服务地址 `http://localhost:8091`）
> 前端项目：marketing-platform-web（本目录）

---

## 1. 项目背景

大营销抽奖系统后端已基于 DDD 架构完成实现，包含抽奖活动、抽奖策略（大转盘）、日历签到返利、积分账户、积分兑换商品等领域能力，通过 HTTP 接口对外提供服务。本项目为配套前端，使用 Vue 技术栈实现面向 C 端用户的营销活动页面。

## 2. 用户角色与登录

| 角色 | 说明 |
| --- | --- |
| 普通用户 | 参与抽奖、签到、兑换商品 |

当前后端无账号体系（接口直接以 `userId` 为入参），因此 V1 采用**简化登录**：首次进入页面时输入/生成用户 ID，存储于 `localStorage`，后续请求自动携带。

## 3. 功能需求

### 3.1 首页 / 活动主页

- 展示活动入口（活动 ID 默认 `100301`，可配置）。
- 进入页面时自动调用活动装配接口 `armory` 完成数据预热（活动库存 + 策略概率装配到 Redis）；若返回失败提示"活动准备中，请稍后重试"。
- 页面骨架：顶部为用户信息栏（用户 ID、积分余额、抽奖剩余额度），底部 Tab 导航（首页/签到/兑换）。

### 3.2 抽奖大转盘（核心功能）

- **奖品列表展示**：调用 `query_raffle_award_list` 获取奖品盘数据，按 `sort` 顺序渲染转盘扇区，展示奖品标题 `awardTitle` 与副标题 `awardSubTitle`。
- **解锁进度**：`isAwardUnlock = false` 的奖品（抽奖 N 次解锁）在转盘上显示锁定态，并展示 `waitUnlockCount`（还差 N 次解锁）。
- **权重规则提示**：调用 `query_raffle_strategy_rule_weight`，取"用户已抽次数 `userActivityAccountTotalUseCount` ≥ `ruleWeightCount` 的最大一档"或"最近将达成的一档"，以滚动条/标签展示"累计抽 N 次必中：xxx、xxx"。
- **抽奖动作**：
  - 点击"立即抽奖"调用 `draw` 接口（JSON：`{userId, activityId}`）。
  - 后端限流 1 次/秒/用户（`RATE_LIMITER`），前端在动画期间禁用按钮（动画时长 ≥ 1.5s）天然规避限流。
  - 成功后根据返回的 `awardIndex`（奖品排序编号）定位转盘扇区，播放旋转动画后停止在中奖扇区。
  - 弹出中奖结果弹窗，展示 `awardTitle`；`awardConfig` 为积分范围配置（如 `1,100`），可辅助展示"随机积分 1~100"。
- **额度展示**：调用 `query_user_activity_account` 展示剩余总额度/日额度（日额度消耗优先），额度为 0 时按钮置灰并引导去签到或兑换。
- **抽奖后刷新**：每次抽奖结束后刷新奖品列表（解锁进度变化）、账户额度、权重规则提示。

### 3.3 日历签到

- 展示当月日历，已签到日期打勾（本地按天记录，当日是否已签到以 `is_calendar_sign_rebate` 接口为准）。
- 点击"签到"调用 `calendar_sign_rebate`（form 参数 `userId`），成功后提示"签到成功，积分将在稍后到账"（返利为 MQ 异步发放，积分余额需延迟数秒或手动刷新）。
- 已签到状态下按钮置灰，提示"今日已签到"。
- 签到送积分 → 积分可用于兑换抽奖次数（3.4）与抽奖消耗，形成营销闭环。

### 3.4 积分兑换商品

- **商品列表**：展示活动 SKU 商品集合（调用 `query_sku_product_list`，见接口文档"待补接口"），展示每个 SKU 的价格 `productAmount`（单位：积分）、剩余库存 `stockCountSurplus`、兑换后获得的抽奖次数（`activityCount.totalCount`/`dayCount`/`monthCount`）。
- **积分余额**：用户信息栏展示积分余额（调用 `query_user_credit`，见接口文档"待补接口"），余额不足时置灰兑换按钮。
- **兑换动作**：点击"兑换"二次确认后调用 `credit_pay_exchange_sku`（JSON：`{userId, sku}`），成功后提示"兑换成功，抽奖额度已到账"并刷新积分余额、账户额度、商品库存。
- **兜底方案**：若后端短期不补 HTTP 接口，前端 V1 可在配置文件中静态配置商品数据（与库表 `raffle_activity_sku` 保持一致）。

### 3.5 我的（用户中心，可选 V1.1）

- 展示用户 ID、积分余额、活动额度（总/月/日）。
- 抽奖记录列表（依赖后端中奖记录查询接口，当前后端未暴露，列入 V1.1 待补）。

## 4. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 响应式 | 适配移动端（375px+）与 PC 端，转盘为主视觉 |
| 性能 | 首屏 ≤ 3s；接口超时 10s；转盘动画 CSS 实现，避免 JS 卡顿 |
| 限流 | 抽奖按钮防抖 + 动画锁定；`RATE_LIMITER(0005)` 错误友好提示"操作太频繁啦" |
| 错误处理 | 统一拦截响应 `code != 0000`，按错误码表映射中文提示；`ERR_BIZ_*` 业务错误逐项提示 |
| 降级 | `DEGRADE_SWITCH(0004)` 提示"活动太火爆，稍后再试"并禁用抽奖 |
| 跨域 | 后端 dev 环境已开启 `cross-origin: *`，前端开发期直连 8091 即可 |
| 环境 | 开发/生产环境通过 `.env.*` 区分 API 地址 |
